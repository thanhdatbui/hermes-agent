# OpenCode Farm Bridge & Fallback Architecture (Local Port 20130)

## Overview & Port Topology
- **9Router**: `http://192.168.110.123:20128/v1`
- **OmniRoute**: `http://192.168.110.123:20129/v1`
- **OpenCode Bridge**: `http://127.0.0.1:20130/v1` (script at `D:/Taadaa/tools/opencode_bridge.py`)

## Why OpenCode Needs a Local Bridge
1. Upstream OpenCode Zen API (`https://opencode.ai/zen/v1`) enforces CLI runtime validation (`HTTP 403 FreeTierError: OpenCode's free tier can only be used from within OpenCode`).
2. External HTTP clients (Hermes gateway, Telegram bot) cannot call the upstream endpoint directly.
3. Solution: `opencode_bridge.py` acts as an OpenAI-compatible HTTP server (`/v1/models`, `/v1/chat/completions`) that routes incoming prompts to the headless CLI wrapper `D:/Taadaa/tools/oc_farm.py`.
4. `oc_farm.py` automatically rotates across 69 farm proxies (35 MikroTik, 32 Mobi, 2 Khoalee) with persistent cooldown tracking (`~/AppData/Local/hermes/oc_farm_cooldown.json`), bypassing daily limits and IP-based HTTP 429 errors.

## Critical Invariants & Pitfalls

### 1. Multi-threaded Server Requirement
- **Pitfall**: A standard `HTTPServer` is single-threaded. When multiple agent sessions (e.g. concurrent Telegram messages, farm alerts, cronjobs) trigger fallback requests simultaneously, the second request is blocked waiting for `oc_farm.py` subprocess execution.
- **Fix**: Always subclass `socketserver.ThreadingMixIn` (`class ThreadingHTTPServer(socketserver.ThreadingMixIn, HTTPServer): daemon_threads = True`).

### 2. Immediate SSE Handshake (15s Client Timeout Prevention)
- **Pitfall**: Hermes client has an internal `connect_timeout = 15.0s`. Large conversation contexts (100k+ tokens) or proxy latency take >15s before the first token is generated by OpenCode, triggering `APIConnectionError: Connection error` / `max_retries_exhausted`.
- **Fix**: For `stream=True`, write an immediate HTTP 200 header and an initial role chunk (`data: {"choices": [{"delta": {"role": "assistant"}}]}\n\n`) within 0.01s before running the underlying CLI process. This warms the connection immediately.

### 3. Model Filter Sanitation
- `opencode models` returns >100 models, including paid/subscription tiers (`opencode-go/*`, `freemodel/*`).
- Expose **only** genuine 100% free models (`opencode/*`) via the bridge:
  - `muse-spark-1.3` (`opencode/muse-spark-1.3-contributor-free`)
  - `nemotron-3-ultra` (`opencode/nemotron-3-ultra-free`)
  - `nemotron-3.5-lightning` (`opencode/nemotron-3.5-lightning-free`)
  - `mimo-v2.6-flash` (`opencode/mimo-v2.6-flash-free`)
  - `big-pickle`, `space-bunny`, `ling-3.0-flash-fin`, `longcat-2.5-preview`.
- Cache with a TTL (e.g., 300s) and support on-demand reload at `/v1/models/refresh`.

### 4. Background Execution
- Start silently on Windows: `wscript D:/Taadaa/tools/start_opencode_bridge_hidden.vbs` or via python background terminal command.
