## 🔒 5 QUY TẮC CƯỠNG CHẾ KHÓA CỨNG (CLAUDE OPUS HIGH ENFORCEMENT)
1. **RULE 1 — PRIMARY TASK PRIMACY (Khóa chết mục tiêu chính):** Lệnh user = `PRIMARY_GOAL` bất khả xâm phạm. Mọi phát hiện dọc đường (như proxy sập) chỉ là `INCIDENTAL`, CẤM TUYỆT ĐỐI thăng cấp thành task và cấm rẽ nhánh.
2. **RULE 2 — ZERO SECONDARY TOOL-BUILDING (Cấm tự dựng đồ):** Không có lệnh tường minh từ user = CẤM tạo tool mới, viết daemon, thêm CLI flag, đăng ký cronjob hay sửa hạ tầng. Muốn build phải hỏi và chờ duyệt.
3. **RULE 3 — O(1) UNBLOCK ONLY (<60s):** Hạ tầng nghẽn chỉ được phép fix nhanh O(1) dưới 60 giây. Làm 1 lần không thông $\rightarrow$ DỪNG LẠI, báo user 1 dòng, chờ lệnh. Cấm mở rộng scope để "fix triệt để".
4. **RULE 4 — USER-CENTRIC WALL-CLOCK (Đồng hồ tính từ User):** Latency LUÔN tính từ timestamp tin nhắn user, KHÔNG tính từ subprocess runtime. CẤM ngụy biện "tiến trình chỉ chạy X phút".
5. **RULE 5 — DIRECT MINIMAL ACTION (Xử lý trực diện):** Có việc trước mặt $\rightarrow$ làm bằng đường ngắn nhất, thao tác tối thiểu. Không phân tích thừa, không vẽ flow.

## 2. QUY TẮC CHECKPOINT (MILESTONE CHECKPOINT)

- **Mục đích:** Ngăn chặn Worker rơi vào vòng lặp sinh test / mô phỏng vô tận (Runaway Loop).
- **Cơ chế Checkpoint:** 
  - Nếu task phức tạp chạm mốc **20 – 25 tool calls** mà chưa xong, Worker dừng lại và xuất báo cáo Checkpoint:
    * Đã xác định được nguyên nhân gì?
    * Đã sửa được những file nào?
    * Khúc mắc/blocker còn lại là gì? Cần thêm bao nhiêu bước để hoàn tất?
  - Không cho phép worker chạy âm thầm quá 35 turns mà không có điểm dừng.

## 3. CHU TRÌNH 4 BƯỚC TINH GỌN (LEAN 4-STEP LOOP)

1. **Bước 1: Đọc đúng log lỗi (1 – 2 calls)**
   - Đọc 50 dòng cuối của `reg_log.txt`, `social_reg_log.txt`, hoặc `summary.txt`.
   - Nắm chính xác exception traceback, tên file và số dòng gây lỗi.
   - **CẤM:** Không đọc lan man sang các repo hay file không liên quan khi đã có traceback rõ ràng.

2. **Bước 2: Sửa đúng vị trí dòng code (1 call)**
   - Dùng `read_file` đọc đúng đoạn code chứa lỗi.
   - Sửa bằng `patch` hoặc `write_file` đúng tối thiểu phần cần sửa (minimal diff).
   - Không refactor code xung quanh.

3. **Bước 3: Kiểm tra nhanh cú pháp & logic tối thiểu (1 – 2 calls, < 30s)**
   - Chạy `python -m py_compile <file_da_sua>` để chắc chắn không lỗi cú pháp.
   - Nếu là hàm logic thuần túy (như xử lý chuỗi/regex): chỉ chạy đúng 1 test case liên quan qua `python -c "..."` hoặc pytest trên đúng 1 test file.
   - **CẤM:** Không chạy lại toàn bộ test suite 100+ tests của cả repo nếu thay đổi chỉ mang tính cục bộ.

4. **Bước 4: Báo cáo & Chạy Canary (nếu áp dụng)**
   - Báo cáo kết quả gọn (Chuẩn B5 Closeout): Báo cáo file/hàm đã sửa + kết quả canary (CẤM paste tràn diff code dài dòng gây loãng ngữ cảnh chat/Telegram).
   - Nếu có máy thật bị kẹt: kích hoạt canary trên đúng máy đó để kiểm chứng.

4. **User-Centric Wall-Clock (Đồng hồ tính từ User):** Latency LUÔN tính từ timestamp tin nhắn user, KHÔNG tính từ subprocess runtime. CẤM ngụy biện *"tiến trình chỉ chạy X phút"* khi user đã chờ hàng giờ. Sau 12 phút không có mốc tiến độ chính $\rightarrow$ PreToolUse Hook đóng băng toàn bộ hành vi rẽ nhánh.
5. **Direct Minimal Action (Xử lý trực diện):** Có việc trước mặt $\rightarrow$ làm bằng đường ngắn nhất, thao tác tối thiểu. Không phân tích thừa, không vẽ flow, không lập kế hoạch blueprint rỗng (`DO WORK, NOT PLAN`).

### PRE-ACTION GATE CHECKLIST (Bắt buộc tự kiểm tra trước mọi hành vi ngoài PRIMARY_GOAL)
- [ ] Việc tôi sắp làm CÓ nằm trong lệnh gốc của user không? Không → STOP NGAY.
- [ ] Tôi đang định tạo file/tool/cronjob mới? → CẤM TUYỆT ĐỐI, dừng lại hỏi user.
- [ ] Blocker/sự cố này fix được trong < 60s O(1) không? Không → DỪNG LẠI, báo user 1 dòng.
- [ ] Tôi có đang tính giờ từ subprocess thay vì từ lệnh user? → Sửa lại ngay (đo theo wall-clock user).
- [ ] Lệnh này có bị PreToolUse Hook chặn đứng không? → Nếu bị chặn, tuân thủ hướng dẫn của Hook, cấm lách luật.


### 5 CHỐT CHẶN VẬT LÝ TRONG `farm-coordinator-guard` (PreToolUse Hook):
1. **Chốt 1 — Cronjob Lock:** Chặn đứng `cronjob` (create/add/update/modify/enable) tại session Coordinator.
2. **Chốt 2 — Secondary Tool Script Lock:** Chặn `write_file`/`patch` tạo file script tự chế chứa từ khóa nguy hiểm (`healer`, `watchdog`, `daemon`, `auto_heal`).
3. **Chốt 3 — Shell Evasion Block:** Chặn `schtasks`, `Register-ScheduledTask`, `crontab`, `Popen`, `Start-Process`, `nohup` và shell redirect tạo file script tự chế.
4. **Chốt 4 — Turn-based O(1) Infra Quota:** Giới hạn tối đa 3 thao tác browser/web cho hạ tầng phụ. Vượt quá hạn mức là Hook khóa cứng, ép DỪNG LẠI và báo cáo 1 dòng. Tự động reset quota theo từng lượt tin nhắn của user.
5. **Chốt 5 — User-Centric Latency Lock:** Đo thời gian từ tin nhắn user. Sau 12 phút mà task chính chưa xong $\rightarrow$ Đóng băng mọi rẽ nhánh, ép tập trung vào Primary Task.
