# Portable Consumer-Repo Maintenance

## Trigger

Use when a consumer repository has machine-specific absolute paths, runtime defaults, scheduler/install wrappers, or configuration drift findings. This applies to Python, PowerShell, shell, and mixed-language workflow entrypoints.

## Documentation-only regression records

When the requested change is a compatibility-regression record limited to repository docs/handoff (no code, tests, runtime, workbook, or device changes), use this narrower path:

1. Snapshot repository identity with `git status --short --branch`, `git rev-parse HEAD`, remote URL, and the exact target files. Preserve unrelated dirty/untracked state.
2. Inspect the compatibility registry's existing `COMPAT-*` IDs before adding an entry. Choose a unique new ID; do not renumber or rewrite unrelated historical duplicates.
3. Preserve byte-level EOL. For CRLF-sensitive Markdown, edit with bytes or explicit `read_bytes()`/`write_bytes()` and verify no bare LF/CR after the final edit.
4. Stage only explicit target paths, never `git add .`; run `git diff --check` before commit and against `HEAD^` after commit.
5. Commit with the user's requested language, push only the requested branch, and independently verify the remote branch SHA.
6. Return the full commit SHA, exact changed files, both diff-check outcomes, EOL counts, and state clearly when tests were intentionally not run because they are outside the authorized docs-only scope.

For the reusable command/report checklist, see `references/docs-only-regression-record.md`.

## Workflow

1. **Prove identity and isolate first.** Resolve the actual repository root with `git rev-parse --show-toplevel`; do not assume the session cwd or a user-provided Windows path is the checkout. If the named files are absent, compare candidate local worktrees by exact path, repository metadata, and entrypoint presence before selecting one; never patch an installed package, cache, backup, or similarly named copy. Read `AGENTS.md`/project rules/runbooks, inspect `git status --short --branch` plus the scoped diff, and preserve every pre-existing dirty change. Create a dedicated worktree and branch from the clean current consumer `main` when the repository policy requires it; if direct edits are explicitly authorized, keep the scope exact and do not reset, format, stage, or overwrite unrelated dirty files. Do not edit a shared/core repository for a consumer-only issue.
2. **When the user explicitly requests a private-machine bootstrap bundle, act on that scope directly.** Do not repeatedly re-litigate generic security warnings after the user has accepted the tradeoff. Put machine-independent setup/configuration, skills, plugins, and requested credential files under a clearly named `deploy/` bundle, add a deterministic setup script, and document exact target paths. Never print secret contents while verifying.
3. **Separate repository payload from runtime state.** Copy only the requested setup artifacts; omit caches, locks, SQLite session databases, logs, and transient process state unless the user explicitly requests them. Make the installer target the current user's paths (`$PSScriptRoot`, `%LOCALAPPDATA%`, `%USERPROFILE%`) rather than hardcoded source-machine paths.
4. **Verify the installer itself.** Parse PowerShell/shell syntax, assert required bundle files exist, run `git diff --check`, and run the repository's canonical checks. If a broad suite flakes or times out, rerun the exact failing target once, then verify each relevant package separately and report the broad-suite blocker precisely.
5. **Trace configuration flow.** Read the flagged scripts, callers, wrappers, and focused tests. Identify default values, CLI flags, environment variables, path normalization, subprocess propagation, and scheduler/task-registration arguments.
6. **Build a tight red check.** Add focused tests that fail before the fix and prove both:
   - defaults do not embed user/machine-specific paths;
   - explicit CLI overrides remain authoritative;
   - environment overrides remain authoritative where supported.
   For non-Python wrappers, assert generated command/path text when invoking registration would be unsafe or unnecessary.
7. **Implement the smallest portable change.** Prefer project-relative paths, standard executable discovery (`PATH`), or explicit configuration. Preserve current behavior, validation, lock semantics, subprocess environment propagation, CLI compatibility, and exact existing asset basenames (including spaces and punctuation). Do not silently rename a workbook/config asset while relocating its directory. Avoid unrelated refactors.
8. **Verify in layers.** Run the focused tests, compile/lint checks, relevant drift/static scans, and `git diff --check`. Then run the broader suite if practical. Distinguish failures caused by missing sibling/reference worktrees or pre-existing fixtures from failures in the changed scope.
9. **Treat validator behavior as separate regression slices.** For a markdown/registry validator, add and run one RED→GREEN test per parsing or ordering rule (for example: decorated label parsing, same-date stable tie-breaking, and heading-level recognition). After the final edit, run both the focused validator test module and the real workspace validator. Report expected external findings/warnings as blockers outside the changed scope, not as a false suite failure.
10. **Preserve byte-level file constraints when requested.** Before writing a CRLF-sensitive file, record CRLF count and whether it has a final newline. Use `Path.read_bytes()`/`write_bytes()` for surgical edits, retain the original final-newline state, then assert there are no bare LF bytes and run `git diff --check`. Keep these checks after the final formatting edit as well as after functional changes.
9. **Ad-hoc fallback.** If no canonical test/lint command is detected, create a temporary `hermes-verify-*` script in the OS temp directory using a safe `tempfile` path. Run it with the repository import path explicitly configured (for example, `PYTHONPATH=<worktree>`), remove it afterward, and report it explicitly as ad-hoc verification rather than suite-green evidence. Always assert the changed behavior directly, including default resolution and explicit environment/CLI override precedence. Keep assertions exact but simple when checking wrapper text (prefer asserting the required basename and forbidden legacy basename separately); if the verifier itself fails due to quoting/escaping or is launched outside the repository, correct the harness and rerun it before diagnosing repository code. Capture cleanup proof with `test ! -e <temp-script>` and print a concise success marker.
11. **Workbook/device identity clarification.** When a workbook row contains both a human machine label and a device identifier, treat the workbook's `device ID` as the direct ADB serial.
12. **Fresh-verification fallback.** If the system marks the workspace unverified or detects no canonical test/lint command, create a focused temporary script under the OS-safe temp directory with a `hermes-verify-` prefix and `tempfile` paths. Exercise the exact changed behavior and edge cases, run it with the repository import path configured, clean it up when possible, and report it explicitly as **ad-hoc verification**—never as full-suite green. Keep targeted tests, full suite, compile/import, and ad-hoc evidence as separate claims. On Windows, use Python `tempfile.mkstemp(prefix="hermes-verify-", suffix=".py", dir=...)`, not hand-built temp filenames; capture a distinctive pass marker and separately verify deletion. For workbook/video fixes, assert the real contract with an isolated temporary workbook/media directory (e.g. fail closed on blank/whitespace device serial and resolve posted=7 to 8.mp4), without live device or upload actions. This fallback applies even when a canonical suite was run earlier in the session: fresh-evidence status is a separate gate, so do not claim the workspace is verified until the required ad-hoc probe has passed.
13. **Workbook parsing edge cases.** For `openpyxl`, enumerate cells/values by index rather than relying on `EmptyCell.column_letter`; canonicalize headers with NFKC, NBSP/whitespace collapse, case folding, and accent-insensitive aliases. Machine-first-row selection must fail closed on a blank serial, while a direct serial selector must remain workbook-local and independent across Tik1/Tik2 files. A `--machine` selector may choose the first matching row, then must resolve to that row's serial; `--single-device` must match the workbook serial exactly. Do not reintroduce an external `device_mapping`/`account_profile` layer unless the user explicitly changes the source-of-truth requirement. Add a fixture with duplicate machine labels to prove first-row selection and a mismatch case to prove fail-closed behavior. For `openpyxl` verification on Windows, close the loaded workbook before temp cleanup. If an ad-hoc verifier fails during temporary-directory cleanup, inspect handle ownership first, close workbook objects on both success and exception paths, then rerun the verifier; do not report the first harness failure as a product failure.
12. **Stateful regression verification.** When a later workflow stage must persist an explicit successful value, do not recompute it from stale source state. Resolve defaults only when the context value is unset; keep duplicate checks at resolution. Add paired assertions for explicit-value preservation and dry-run no-write behavior. If the workspace is marked unverified or no canonical command is detected, use a temporary OS-safe `hermes-verify-` script with `tempfile`, run it with the repository import path configured, capture its distinctive pass marker, clean it up, and label the result **ad-hoc verification**—separate from suite status.
13. **Live preflight boundary.** For device workflows, implement a separate `--preflight` path that validates mapping, ADB state, workbook/video resolution, and locks, but does not construct the live state machine or perform app/UI/media/workbook-write/upload actions. Print an explicit no-upload marker. Verify both the focused CLI path and a temporary `hermes-verify-` fixture script; passing the suite alone is insufficient.
14. **State-machine safety gate (rotation only).** For consumer workflows that touch devices, keep only the `rotation_locked` readiness check in the consumer state machine. The `locked_or_secure` gate, `is_device_locked` flag, `_allows_no_credential_swipe`/`_no_credential_swipe_retries` methods, and `allow_no_credential_swipe` config have been **removed** — do not reintroduce them. On `prepare_device()`, log both `rotation_locked` and `unlock_state` for diagnostics but only guard on `rotation_locked is not True` (→ `is_ui_unavailable` + `MANUAL_REVIEW`). Wrap execution in an outer `finally` that releases all acquired leases; retain stale/foreign lock artifacts unless cleanup was explicitly requested. Do not test this path with live devices, uploads, passwords, or credential bypasses; use deterministic fakes.
10. **Report precisely.** Include exact worktree path, branch, changed files, commands and real outputs, focused/full-suite status, blockers, and confirmation that no commit or push occurred. Preserve unrelated changes.

## Offline Queue-Backed Adapter Debugging

For offline consumer flows whose fake adapter returns UI XML from a queue, treat snapshot consumption as part of the state contract:

1. Instrument each `dump_ui()` with before/after queue indexes and a compact node summary (`text`, `content-desc`, `index`). Trace navigation waits, classification, tap helpers, verification, popup dismissal, and reloads.
2. If one helper classifies a snapshot and a later helper acts on the same UI state, reuse the already-captured XML/nodes instead of recapturing. A redundant dump can shift every later fixture and produce misleading `unknown` or `manual` results.
3. Do not pad a fixture queue or weaken the expected result to hide misalignment. Keep exact assertions for the business result, budget, dedupe/skip outcome, and final queue position when queue consumption is load-bearing.
4. After alignment is fixed, inspect semantic selector collisions: substring matching such as `Follow` can also match `Đã follow`. Classification must establish the state before applying an action selector.
5. When a system verification gate reports stale/unrecognized evidence, use the existing fresh-evidence fallback with a focused `tempfile.mkstemp(prefix=\"hermes-verify-\", suffix=\".py\", dir=tempfile.gettempdir())` harness. Run it from the repository root with an explicit import path, assert the exact changed behavior, clean it in `finally`, and report it as **ad-hoc verification**, separate from suite status.

## Workflow Note

For Hermes cross-machine replication, the durable class-level pattern is: source checkout + `deploy/` bootstrap script + user-facing config/skills/plugins + explicit credential payload when the user has authorized private-repo bundling. A repo checkout alone does not reproduce Hermes user state. Prefer `%LOCALAPPDATA%\hermes` and `%USERPROFILE%\.codex` on Windows, and install Hermes editable from the checkout instead of silently selecting a different global/PyPI installation.

### Multi-machine consumer farms: shared code, partitioned state

For two Windows phone-farm hosts running the same TikTok consumers, use one Git remote with one independent local checkout per host. Share source code, reviewed skills, tests, and config templates through Git; keep each host's workbook, runtime state, locks, checkpoints, receipts, logs, ADB mapping, Hermes state, credentials, and Telegram bot local. Do not put the working tree or `.git` directory in OneDrive.

Treat Excel as an operator-managed source/ledger, not a concurrent database. A single `.xlsx` concurrently written by two hosts is unsafe even when machine ranges do not overlap: openpyxl rewrites the workbook, OneDrive does not perform semantic row merges, and stale reads can lose state. Prefer one workbook per host with disjoint account/machine ownership, or a read-only master exported into host workbooks. If a shared authoritative pool is required, migrate runtime ownership/leases/status to SQLite/MariaDB with transactions and leave Excel as import/export.

- Make consumers host-config-driven rather than forked. A tracked `config.example.yaml` defines the schema; each host supplies an ignored local config containing `host_id`, machine range, workbook path, runtime root, and ADB path. The worker must print and validate the effective host/range/workbook before live execution and fail closed on ownership mismatch. See `references/multi-machine-state-and-git-gate.md` for the data partition and commit-gate checklist.

### Stale device-lock reconciliation (Tiktok-video upload batch)

When a canonical upload batch dies mid-run it leaves **dead-owner `tiktok-upload` locks** (`status=running`, `owner_active=True`, PID dead) that make the next batch `SKIPPED_LOCKED`. Fix with **exact-attribution guarded reconciliation**, never raw-delete, never global unlock. Key lessons:
- **`open_failed_locked_lock` does NOT reclaim dead-owner `running` locks** — it only clears terminal `failed_locked`. Use core dead-owner reaping via `acquire_device_lock` (PID probe decides liveness, NOT the lock's own `owner_active` flag, which is the stale lie from the dead batch).
- **Reconcile ONLY targets in the current batch machine list**; preserve foreign (`tiktok-luot nuoi acc`, `Tiktok_Reg`) and other-workflow (avatar/nuoi) locks.
- **Monkeypatch bypass trap:** a reconcile helper with a *local* `from automation_core.device_lock import acquire_device_lock` inside the function ignores `monkeypatch.setattr(module, "acquire_device_lock", fake)`, so the test reports `released==0`. Import at module top level.
- **`patch` tool can swallow a following class header** (it ate `class TestConfig:` when inserting a large test block); re-read the patched region and restore the declaration.
- **Tests may resolve under a different `unittest.TestCase` class** yet still run; assert with `file.py::ClassName::method`.
- Full recipe + RED→GREEN tests: `references/stale-device-lock-reconciliation.md`.

### Offline versioned-wheel bump and consumer repin (shared core → consumers)

When a fix lives in a shared core (e.g. automation-core) as dirty source and the deliverable is a versioned wheel plus an updated consumer file-pin (verified 2026-08-23, 0.4.45 → 0.4.46):

1. Baseline BOTH repos first (`git status --porcelain` + scoped diff); classify every pre-existing dirty file as preserve-only before touching anything.
2. Bump ONLY the pyproject `version` line (single-line patch). Build with `python -m build --wheel --outdir dist .`; use `--no-isolation` only when setuptools/wheel are known-present locally (default isolated build may hit the network).
3. Verify BEFORE copying: read `*.dist-info/METADATA` from the wheel via `zipfile` — the version is on line ~3 (`Metadata-Version`, `Name`, `Version`), not the first line; also grep the packaged source for the fix marker. Then copy to the EXACT artifact path the consumer pin names and sha256-compare source vs copied.
4. Repin the consumer requirements `file:///` line AND its version-comment in one edit.
5. Focused tests only: the core named module + consumer tests directly covering the changed seam (vpn/preflight/feed-session class). No ADB/live unless the contract says so.
6. **Provenance WITHOUT installing:** never trust a bare `import automation_core` in the session shell — editable installs (`__editable__.pth`) and persisted PYTHONPATH entries resolve it to the SOURCE tree, not any wheel (observed: shell reported 0.4.45 while validating a 0.4.46 wheel). Extract the exact pinned wheel to a temp dir with `zipfile.ZipFile.extractall`, run a fresh subprocess with `PYTHONPATH=<extract>`, print `importlib.metadata.version` + `module.__file__`, assert the path is under the extract dir, then delete the temp dir. Wheels with empty `Requires-Dist` need no install to be import-probed this way.
7. **Dual-wheel A/B failure attribution:** when consumer focused tests fail, extract BOTH the old and new wheels to separate temp dirs and run the identical failing nodes twice, once per PYTHONPATH. Same failure set under both = pre-existing (typically consumer dirty WIP outside scope); failures only under the new wheel = your regression. Strong bonus signal: if the OLD-wheel run dies at collection with `ImportError: cannot import name 'X' from automation_core.<mod>` while the new wheel imports fine, the dirty consumer source is AHEAD of the old pin — the version bump is the enabling change for the whole suite, and the old wheel cannot act as baseline runtime.
8. Close with `git diff --check` + changed-path inspection in both repos; report artifact path, version, hashes, exact commands/outputs, and pre-existing-vs-regression classification separately.

Full command transcript + case study: `references/versioned-wheel-offline-deployment.md`.

Contract that survived plan + diff audit:

- `assert_machine_in_range()`: machine outside host range → error BEFORE any device action.

Pitfalls from this build:
- **Stale env is the #1 corruption vector**: user/env may already export `TIKTOK_REG_*` pointing at machine-A canonical paths; the host config must override them loudly.
- **ImportError fallback trap**: `except (mod.HostConfigError, ImportError)` raises NameError when the import itself failed (name unbound). Import in its own try, set `mod = None`, then branch.
- **`git add <file>` stages the WHOLE working-tree version**: a pre-existing dirty refactor in the same file rides into the commit (Tiktok_Reg `_configured_workbook_path` refactor). Acceptable only if the audit prompt covered the FULL staged diff — capture `git diff <file>` BEFORE editing to know what was already dirty.
- **Audit for plan/diff, not just commits**: `run-ag-audit.sh` diffs a commit; for a plan or uncommitted diff use `ag_audit_direct.py <prompt-file> <model> <out> <timeout>`. The wrapper may print `AG_AUDIT_VERDICT=UNPARSEABLE` when the response's first line is a heading (e.g. `## VERDICT`) even though the body says APPROVED — read the response file before treating it as failed (tái xác nhận 2026-08-12: body dòng cuối `**AG_AUDIT_VERDICT=APPROVED**`, wrapper in UNPARSEABLE — grep response file, không coi là fail).
- **`ag_audit_direct.py` prompt path phải là Windows form (`D:/Taadaa/...`), KHÔNG phải MSYS `/d/Taadaa/...`** (verified 2026-08-12): Python Windows không hiểu `/d/...` → `FileNotFoundError` dù file tồn tại. Trả lỗi này → chạy lại với `D:/...` path, không phải dấu hiệu audit hỏng.
- **`git pull --rebase` fails with "unstaged changes" on already-dirty repos** (both Tiktok-video and Tiktok_Reg hit this). Fetch first; if remote hasn't moved, plain `git push` is safe — do NOT stash/commit foreign dirt just to satisfy the rebase gate.
- **Windows case-insensitive FS**: `HANDOFF.md` and `handoff.md` are THE SAME file — `git status` shows the repo's tracked casing (`handoff.md` in Tiktok_Reg). Check tracked casing before appending docs.
- **Session env may already carry `TIKTOK_REG_*`** (from Windows user env/profile, not from scripts): `env | grep -i TIKTOK_REG` before testing apply_env, otherwise a "host config wins" test looks like it failed (it actually preserved a stale override).

### Workbook relocation into the host partition (phase 2, 2026-08-11)

Migrating the live workbooks into `TaadaaData/<host>/` (kibe) after the host-config landed:

- **`setx`/registry env changes apply ONLY to new processes.** The running Hermes gateway (pythonw) keeps the old env — deleting the old workbook paths it still references breaks its cron feed/upload. Order: copy → set env → verify with a FRESH process using explicit env (`env TIKTOK_REG_TRACKING_WORKBOOK=... python -c ...`, never the current shell which still holds old env) → keep old files until the gateway restarts and the new path has run for days.
- **Two copies of the same workbook can be content-identical but checksum-different** (openpyxl re-save rewrites bytes): `taikhoan_run_safe.xlsx` OneDrive vs repo-local had 0 diff rows but different md5. Compare content (row dump via openpyxl), not checksum, before treating them as equivalent.
- **Scan live processes before moving files in use**: `wmic process where "Name='python.exe' or Name='pythonw.exe'" get ProcessId,CommandLine` — `gan_proxy_fleet watch --mapping PROXYgandienthoai.xlsx` re-reads the mapping every 30s. If the user authorizes moving a watcher-held file, the procedure is **kill → move → relaunch with the NEW path in the command**: `taskkill /PID <pid> /F` (single slash — MSYS eats `//`), `mv`, then relaunch the exact original command with `--mapping` pointing at the new path. The relaunched watcher may exit `BLOCKED: watcher singleton is already held` if a duplicate instance grabbed the lock first — that exit is the singleton guard working, one active watcher is enough.
- **Windows YAML double-quoted paths need 4 backslashes per segment** (`"D:\\OneDrive\\Tiktok\\Tik1.xlsx"` parses to `D:\OneDrive\...`). Byte-pattern guessing around `\` corrupted 15 `config-machine-*.yaml` (invalid `\k` escape → `yaml.ScannerError`). Fix with regex on the full quoted value, then verify EVERY file with `yaml.safe_load` + `Path(...).exists()` before moving on — parse success is the only reliable check.
- **Set ALL env aliases pointing at the same canonical file** — `TIKTOK_TRACKING_WORKBOOK` / `TIKTOK_XLSX_PATH` / `TIKTOK_ADD_WORKBOOK` / `TIKTOK_PASSWORD_WORKBOOK` all alias `taikhoan_dat_v2_updated .xlsx`; missing one leaves a stale path (find them via `reg query HKCU\Environment | grep -iE 'WORKBOOK|XLSX'`).
- Keep a pre-move snapshot in `TaadaaData-Snapshots/`; md5 the copy vs original before deleting the source.

### Cron sync path fixes: stale process env beats script defaults (2026-08-12, taikhoan-run-safe-sync)

Symptom: a no_agent cron watchdog fails `TAIKHOAN_SYNC_SOURCE_STAT_FAILED` (or similar) with the OLD path even AFTER the script defaults were edited to the new paths. `reg query HKCU\Environment` already shows the NEW path, yet the failure persists.

Root-cause chain — check ALL layers, not the first:
1. **Script defaults** (`os.environ.get("TIKTOK_TRACKING_WORKBOOK", default)`): fix with byte-level EOL-preserving edits (CRLF pitfalls above).
2. **Registry-correct ≠ process-correct.** The Hermes gateway (pythonw) captured env at startup; the process running the cron still has old values even when the registry is fixed. Runtime env override WINS over script defaults — the new default never takes effect.
3. **Fix WITHOUT restarting the gateway** (live-batch rule): patch the cron launcher at `~/AppData/Local/hermes/scripts/<job>_launcher.py` — a LOCAL hermes file, NOT the git-shared repo wrapper — to inject env overrides: `env = dict(os.environ); env["VAR"] = <new path>; subprocess.run(..., env=env, ...)`. The launcher is the correct machine-specific injection point; the repo wrapper keeps portable defaults.
4. **Verify by running the LAUNCHER itself, not the wrapper**: first run exit=0 + output workbook mtime updates + state JSON (`runtime/*-sync-state.json`) `source_sig`/`last_sync` refresh; second run exit=0 + stdout EMPTY (silent watchdog contract — no_agent cron must not spam).

EOL nuance: `.bat` files can be MIXED EOL (7 CRLF + 5 bare LF observed on `run_74machines.bat`) — check EOL per file before asserting pure CRLF/LF; a byte-edit script that asserts pure EOL crashes on mixed files. For mixed files skip the purity assert, replace on bytes only, and re-verify the old path bytes are gone + diff is scoped.

### Git gate for autonomous edits

Before editing: `git fetch` + `git pull --rebase`. Before commit: run focused checks and an independent audit with a machine-parseable verdict. `REJECT`/`MINOR_FIXES`/unparseable output blocks commit; fix and re-audit. Only `APPROVED` permits commit. After commit, fetch/rebase again; if the diff or commit base changes, re-test and re-audit before push. A rejected push means rebase and repeat the gate; never force-push. Stage explicit paths only, never workbooks, runtime state, credentials, or `git add .`.

### Autonomous implementation → audit → commit loop

When the user asks the agent to continue autonomously, do not pause for routine progress updates or ask the user to resolve ordinary implementation/audit issues. Run the class-level loop yourself: (1) freeze the approved plan and exact allowlist; (2) capture byte-level rollback preimages before editing; (3) dispatch one isolated implementation worker; (4) independently re-read current bytes, status, diff scope, hashes, tests, and evidence after the worker exits; (5) send those exact immutable bytes/evidence to an independent AG Opus audit; (6) if the verdict is `REJECT`, `MINOR_FIXES`, transport failure, stale-hash, or unparseable, diagnose and retry/fix in the worker, then rebuild the audit binding; (7) only an exact first-line `APPROVED` permits explicit-path staging/commit; (8) re-verify the resulting commit and rerun the scoped tests. A worker's self-report, process exit, queued notification, or stale hash is never completion proof. Any post-audit byte edit invalidates the verdict and requires re-hash/re-audit. Keep the user-facing channel quiet except for a real blocker or a completed gate.

For Windows repos with spaces in the path, keep coordinator scripts and audit prompt files on Windows-form paths (`D:/...` or `C:/...`) when consumed by Windows Python; use Git-Bash `/d/...` only inside shell commands. Build prompts from line lists or raw-safe path values rather than ordinary Python string literals containing `C:\Users\...`, which can trigger `\\U` Unicode-escape parsing. Preserve foreign dirty files and never infer that a worker worktree patch landed in the parent until the parent independently verifies the target path, hash, status, diff, and tests. If the audit transport returns HTTP 404/timeout or the wrapper emits an unparseable result, classify it as transport/binding failure—not an implementation verdict—then correct the route or prompt binding and rerun the exact audit.

Treat the repository `skills/` tree as the source of truth for **shared, reviewed skills**. Treat `%LOCALAPPDATA%\hermes\skills\` as the runtime/user layer: new skills may first appear there and diverge per machine. Before sharing a skill, copy only its authored payload (`SKILL.md`, `references/`, `scripts/`, `templates/`, `assets/`) into the repo; do not sync runtime metadata such as `.usage.json`, `.usage.json.lock`, `.curator_state`, or `.bundled_manifest`. After `git pull`, explicitly sync repository skills into the active Hermes home or run `/reload-skills`; pulling the source checkout alone does not update the live user-level skill tree.

Keep machine-specific experiments and skills local. Promote a skill to the repo only after it is generalized, removes machine-specific paths/secrets, and is useful across machines. If both machines edit the same shared skill, use normal Git pull/rebase conflict resolution rather than silently overwriting one machine's runtime copy.

Do not claim full verification merely because focused checks pass. Record broad-suite timeouts separately from package-level passes; retry the exact flaky test before changing code.

## Audit-Fix Test Reconciliation (stale tests → new safety contract)

When a follow-up round must reconcile a test suite with **already-changed** production code — fail-closed safety fixes landed by an audit-only round (e.g. `Sol R6 blind re-audit`), not by you — the stale test is the bug, not the production change. Update the test/fixture to the fix's contract and add regression tests pinning each finding; **never weaken production safety to pass a test**. Verified recipe (Tiktok-video A7, 2026-08-09): `references/audit-fix-test-reconciliation.md`.

Rules proven by running sessions:
- Batch-reproduce the stale set with one `pytest -k "t1 or t2 or ..."`, then classify each failure: contract/enum changed, new evidence the test must supply, or missing helper (e.g. method never landed — add it or fix the call).
- New fail-closed contracts usually demand NEW evidence the old test never supplied (pre/post artifacts, checkpoint persistence, markers). Supply it in the test (`monkeypatch` + `tmp_path`, e.g. wrap `_capture_soft_reboot_artifact` → `tmp_path / phase`) — the fixture is the fix, not the behavior.
- Add one regression test per audit finding that pins the fail-closed action (no-second-reboot for same signature; VERIFIED requires full artifact+verifier proof; fail-closed when evidence missing or checkpoint save fails; post-action FRESH frame passed to the verifier; non-caption focused EditText never validates caption).
- Multi-hunk `patch` (V4A) fails with "Found N matches" when hunks share a duplicated anchor — unique the context or switch to a Python editor script after ≤3 failures.
- Do not inline payloads in bash heredocs (`python - <<'PY'` breaks on nested quotes/triple-strings → `unexpected EOF`); write an `_edit_*.py` with the `write_file` tool, run it, delete it.
- EOL-preserving bulk edit (hard "preserve EOL" requirement): `open(p, "r", encoding="utf-8", newline="")` read + `open(p, "w", encoding="utf-8", newline="")` write round-trips byte-exact; `Path.read_text(newline=...)` raises `TypeError`; assert `"\r\n" not in text` (pure-LF) and no bare-LF regex (pure-CRLF) before/after. The `patch` tool is inconsistent on CRLF files (injected LF lines into a CRLF source this run) — do not trust it for EOL-critical files.
- **`Path.read_text()`/`write_text()` silently convert CRLF→LF — never use them for EOL-critical files** (verified 2026-08-09, Tiktok-video R9b): `Path.read_text(encoding=...)` applies universal-newline translation (a CRLF file reads back as `\n`-only text) and `write_text(..., newline='')` then writes plain `\n` → the file flips CRLF→LF QUIETLY with no error. `read_text()` also does NOT accept `newline=` (TypeError), so there is no in-place fix — the trap looks harmless until `git diff` shows the whole file rewritten. Correct sequence: detect EOL first (`is_crlf = b'\r\n' in path.read_bytes()`), then either (a) edit on `bytes` with `\r\n` in anchors, or (b) decode manually `text = data.decode()` → patch on `\n`-normalized text with explicit `text.replace('\r\n', '\n')` up front → re-encode with `.replace('\n', '\r\n')` before `write_bytes()` when `is_crlf`. Always verify EOL AFTER the write (bare-LF count == 0 for CRLF files, `"\r" not in raw` for LF files) and confirm `git diff --stat` doesn't show a whole-file rewrite.

## Windows Space-Path Repos and hermes-verify Bootstrap (verified 2026-08-09)

Repos with a space in the path (e.g. `D:\Taadaa\tiktok-luot nuoi acc`) break several default tool paths; use these instead:

- **git from MSYS bash**: `git -C '/d/Taadaa/...'` fails with `cannot change to ... No such file or directory`, but `git -C 'D:/Taadaa/...'` (Windows form, forward slashes) works. `stat`/`ls` on the `/d/...` form succeed — only `git -C` is picky.
- **search_files/ripgrep**: fails on these paths with `IO error for operation on /d/...: The system cannot find the path specified` — and it is NOT limited to space paths (verified 2026-08-11 on `D:\Taadaa\Tiktok_Reg`, no spaces): the tool cannot reach the D: drive at all on this host, so for any `D:\...` repo just use `terminal` grep/ls directly instead of retrying search_files. Reliable grep fallback: run the repo venv python with a heredoc that does `Path(p).read_text(encoding="utf-8").splitlines()` and scans `enumerate`d lines for the pattern, printing `lineno|line` — the exact line numbers double as `patch` anchors.
- **pytest node ID**: this repo's suites are `unittest.TestCase` classes, so `pytest file.py::test_name` reports `ERROR: not found`; use `pytest file.py::ClassName::test_name`. Find the class name by scanning for `class ` lines above the method.

hermes-verify bootstrap pitfalls (bootstrap heredoc → tempfile script → subprocess):

- Create the script with `tempfile.mkstemp(prefix="hermes-verify-", suffix=".py", dir=tempfile.gettempdir())`, write the inner source as a raw triple-quoted string (`r'''...'''` keeps backslashes/quotes intact), run it via `subprocess.run([sys.executable, path])`, then `os.unlink(path)`; print `cleaned: <bool>` and propagate the exit code.
- **Wrap the inner script's behavior checks in `def main():`** — a nested `def side(...)` using `nonlocal seen` at module level raises `SyntaxError: no binding for nonlocal 'seen' found` (module scope is not a closure scope). One harness rerun cost; it is a harness bug, not a product failure.
- When the inner script imports the repo's test helpers, add BOTH `<repo>/python_runner` and `<repo>/python_runner/tests` to `sys.path` — the test module itself does `import _path_setup`, which is not on the default path.
- The verification monitor treats the temp script itself as a changed path; deleting it after the run (and proving `cleaned: True`) satisfies the gate — a prior suite pass alone does not.

## Bulk UI-Capture Timeout/Deadline Maintenance

For a user-provided timeout increase spanning multiple consumer repositories, use an explicit per-repo manifest rather than a global numeric replacement. Record repository, file, symbol/call site, current value, requested value, and protected exclusions. Treat scanned line numbers as navigation hints: inspect the current effective call path because dirty worktrees or concurrent edits can shift lines or replace a literal with a constant. Classify sites as shared capture APIs (`capture_ui_xml`, `capture_ui_observation`, `dump_current_ui`), adapter wrappers, or raw shell `uiautomator dump`; do not silently broaden a shared-capture request to every unrelated wait or raw shell command.

Before the first write, snapshot each repository's status, scoped diff, file bytes/EOL counts, and target anchors. If a target file is already dirty, preserve unrelated hunks and use a unique content-asserting byte edit; never reset, checkout, format, or rewrite the whole file. For CRLF or mixed-EOL files, patch bytes and verify the original EOL pattern after writing. After editing, re-scan both requested new values and protected invariants (budgets, coordinate fallbacks, settle `0.3`, and boot timeout `90`), then run per-repo `py_compile`, relevant focused pytest targets, and `git diff --check`. Report line drift, raw-shell capture findings, and incomplete verification explicitly. Never claim completion if a tool-call/session limit occurs before the write or verification phase. Identical timeout literals repeat across many sites in one file (same `maximum=8.0` line at 2+ line numbers); the count-assert refuses them — extend the anchor with a neighboring unique line (next/prev line, `self.timeout` vs `timeout`, or a third context line) instead of weakening the assert. Prior workers may have already bumped values in the dirty tree: anchor on current working-tree bytes, and attribute foreign hunks in `git diff` to pre-existing dirt. See `references/bulk-timeout-maintenance.md`.

Offline-Tested Read-Only ADB Tools (new-file scope)

For building a new `tools/<name>.py` + offline test in a consumer repo (verified 2026-08-12, tiktok-follow `dump_selectors.py`):

- **Never `from tools import X` when repo `tools/` has no `__init__.py`** — site-packages `tools` shadows it (`ImportError`). Load the module by path with `importlib.util.spec_from_file_location(...)`, then monkeypatch `module.subprocess.run` (the module holds a direct subprocess reference).
- **Assert the exact full command list** from the fake `subprocess.run` recorder (read-only commands only) plus a destructive-token guard (`tap|keyevent|swipe|force-stop|launch|reboot|clear`) — do not just assert "it ran".
- **Deterministic artifact tests**: monkeypatch the module's `utc_timestamp()` to a fixed string, then assert every output filename contains ts + `sha256(serial)[:12]` and the summary carries the full serial hash — never write the raw serial.
- **Failure = zero partial artifacts**: on ADB rc!=0 assert `list(out_dir.iterdir()) == []`, `BLOCKER` + failing command on stderr, and exit != 0. Never fake a PASS.
- **Windows path-case trap**: the real repo path is `D:\Taadaa\...` (capital T) — FS ops work with any casing but string assertions fail on case mismatch. In tests and ad-hoc verifiers, compare paths against the module's own resolved `repo_root()`/`Path(__file__)`, never a hardcoded path string you typed.
- Full recipe (importlib loader snippet, test design, coordinator marker handoff for docs/ui-compatibility updates): `references/offline-adb-probe-tool.md`.

## CLI Live-Session Wiring and Safety Contract

For a consumer CLI that exposes both a read-only plan and a live session, treat the CLI boundary as its own class of portability/safety work:

1. Keep `Adapter`, `State`, and `Engine` construction strictly after the `dry_run` return. Focused dry-run tests must monkeypatch all three constructors plus `subprocess.run`, assert no call occurs, and assert the configured runtime-state directory remains absent.
2. Keep live seams patchable at the CLI module boundary and assert exact wiring: `Adapter(adb_path, row.serial, package)`, `State(machine, cfg)`, `Engine(adapter, cfg, mapping, state)`, then `run_session(machine, cfg.mode)`. Do not override a production-safe lock default with `locks_enabled=False`.
3. Emit an allowlisted, machine-scoped `FOLLOW_RESULT` JSON line exactly once with `machine/status/reason/followed/skipped/blocked/details`. Keep safe plan output separate; never serialize complete workbook rows or raw UI/XML.
4. Separate failure stages in tests and exit codes: pre-engine config/mapping errors report `CONFIG_ERROR` to stderr and exit `2`; statuses returned by the engine exit `0` only for `OK` and `SKIPPED_LOCKED`, otherwise `1`, including engine `CONFIG_ERROR`. An absent optional mode must be represented by an engine result, not an `ImportError` traceback.
5. When a fresh-evidence gate requests a temporary verifier, run a fake-only live probe and a dry-run guard probe from `%TEMP%`, with explicit repository import-path bootstrapping, cleanup proof, and separate labels for **Ad-hoc verification: PASS**, focused tests, compile, and diff checks. The reusable probe outline is `references/cli-live-session-verification.md`.

## Safe-by-default Entrypoints and Offline Plan Mode

For consumer repos whose batch entrypoint launches live fleet work by default (`run --all` with device locks), flip the default to a read-only plan and make live behavior opt-in (verified 2026-08-12, gan-proxy):

- **Batch default = `plan --offline`; live only on explicit env opt-in** (`if /I "%GAN_PROXY_MODE%"=="run" (... run --all ...) else (... plan --offline ...)`).
- **Env-driven `DEFAULT_*` with fallback preserving the old value** (`os.environ.get("GAN_PROXY_X", <old-path>)`) so the Python CLI and the bat wrapper share one source of truth; a dependent script that imports `DEFAULT_*` from the main module stays in sync without edits. Check repo precedent for env config first (e.g. an existing `GAN_PROXY_VALUE` secret-passing convention).
- **`--offline` flag for plan mode**: plan normally probes ADB per device; the flag makes it parse-only (`state=mapped`), so plan/help/parser run with zero device access.
- **Never execute a live opt-in branch inside a test** — it acquires real device locks and writes runtime reports even with fake serials. Verify the run branch statically (string assertions on wrapper text); only the read-only plan branch may be exercised via subprocess. If a test accidentally creates locks/reports, delete only artifacts whose ownership matches (fake serial + dead pid + test tmp mapping path).
- **MSYS `/tmp` paths are invisible to Windows subprocesses**: for any `cmd.exe`/`python.exe` subprocess needing a temp file, use Python `tempfile.mkdtemp()` (Windows-native), never git-bash `mktemp`.
- In an ad-hoc verifier harness, keep separate subprocess helpers for "run the CLI script with subcommand args" vs "`python -m`/`-c`" — prepending the script path to every call breaks `py_compile`/import probes (harness bug, not product failure).

Full session detail: `references/safe-default-entrypoint-offline-plan.md`.

## Focused Identity-Validation Probes

For source/config identity changes, make the temporary verifier model the real parser payload rather than calling a private helper in isolation. Cover acceptance of repeated row numbers on different machines, rejection of duplicate `(machine, account_row)`, global duplicate `account_id`, machine↔serial one-to-one violations, and parser row boundaries. Keep each rejection fixture valid through earlier schema/state checks: if the parser validates state-revision IDs before account uniqueness, deliberately supply a minimal valid state list (or adjust only the temporary fixture) so the probe reaches the intended invariant. A failure at an earlier gate is a fixture-ordering problem, not evidence that the production invariant is wrong. Report the first failed probe honestly, fix the harness, rerun, and retain cleanup proof.
