# Gate 6 Fail-Closed Egress Guard: Root Cause Analysis & Physical Hash Verification

## 1. Root Cause of Gate 6 Egress Bypass (Claude Sonnet 5.5 Audit)

### Finding 1: Denylist / Keyword Trap (Fail-Open)
- Initial implementations of the Gate 6 output check used a denylist regex that only triggered on explicit completion declarations (`"đã xong"`, `"đã hoàn tất"`, `"đã đổi"`).
- When the assistant provided descriptive, narrative, or progress-oriented summaries without explicitly saying "done" (e.g., *"Báo cáo tổng kết hiện trường...", "kịch bản đã được thực thi...", "đã tắt popup trả về profile sạch..."*), the denylist check failed to match.
- This resulted in a **Fail-Open** vulnerability: changing narrative tone allowed text-only responses to bypass the requirement for physical visual evidence.

### Finding 2: Lack of Physical Disk & Content Hash Verification
- Earlier gate logic verified receipts based purely on in-memory or registered metadata.
- If a token `MEDIA:<path>` was emitted pointing to a non-existent file, an empty file, or a file whose content had been altered/tampered with after OCR inspection, the gate could pass invalid evidence.

---

## 2. Architecture of the Hardened Egress Filter (`guard_media_vision_gate.py`)

### 1. Broad Action & Entity Coverage (Fail-Closed)
- Expanded `ACTION_COMPLETION_PATTERNS` to cover all forms of status reporting, progress tracking, and scene descriptions:
  `bao cao`, `tien do`, `hien truong`, `ket qua`, `kich ban`, `da ghim`, `da tat`, `da dong`, `tong ket`, `cap nhat`, `hoan tat`, `thuc thi`.
- Paired with 21 entity patterns (`may`, `nick`, `video`, `popup`, `story`, `thiet bi`, `kenh`, `bio`, `tieu su`).
- Normalized with diacritic stripping and `đ -> d` normalization to catch all linguistic variants.

### 2. Physical File & Freshness Gate
Before accepting any `MEDIA:<path>` tag in output:
1. `_media_file_verdict(path)` verifies `Path(path).is_file()` and checks file size > 0.
2. The current SHA-256 of the file on disk is computed.
3. The computed SHA-256 is matched against the HMAC-signed receipt generated by the vision/OCR inspection tool (`browser_vision` or WinRT OCR).
4. If the file is missing, empty, or has a mismatched hash, the gate returns `INVALID_MEDIA_FILE` with exit code 2.

---

## 3. Operational Rule for Coordinators & Workers

- **Never summarize UI state without `MEDIA:`**: Any response discussing an on-device UI screen, account profile, video status, or popup MUST carry at least one valid, freshly inspected `MEDIA:<path>` tag.
- **Inspect Before Registering**: The inspection tool (`browser_vision` or WinRT OCR) must run on the actual image, followed by receipt registration before formulating the final message.
