# Reconciling Stale Site-Packages Shadowing Live Editable Source

## Root Cause & Symptom
When developing or updating `automation-core` (`D:\Taadaa\automation-core`), runners or background jobs executing via virtualenv `D:\Taadaa\python-envs\automation` may silently execute stale code even after commits are merged.
- **Symptom Example:** Alert sender continues to send 2 separate Telegram messages (legacy behavior) instead of the single consolidated photo alert (Case 84 & 85), or imports do not reflect newly added functions.
- **Root Cause:** A physical folder `D:\Taadaa\python-envs\automation\Lib\site-packages\automation_core` exists. Python's module resolution resolves the directory inside `site-packages/` directly, ignoring any `__editable__.automation_core-*.pth` file pointing to `D:\Taadaa\automation-core\src`.

## Detection Probe
Run inside the target virtualenv:
```bash
/d/Taadaa/python-envs/automation/Scripts/python.exe -c "import automation_core; print(automation_core.__file__)"
```
- **Shadowed (Bad):** `D:\Taadaa\python-envs\automation\Lib\site-packages\automation_core\__init__.py`
- **Live Editable (Good):** `D:\Taadaa\automation-core\src\automation_core\__init__.py`

## Remediation Workflow

### 1. Remove Static Package Directory
```bash
rm -rf /d/Taadaa/python-envs/automation/Lib/site-packages/automation_core
```
> **Note on Direct Copy vs Editable:**
> If a downstream workflow or manual sync script copies files directly (`cp -rf D:/Taadaa/automation-core/src/automation_core/* /d/Taadaa/python-envs/automation/Lib/site-packages/automation_core/`), ensure the target directory exists (`mkdir -p /d/Taadaa/python-envs/automation/Lib/site-packages/automation_core`) or `cp` will fail. However, note that doing this creates a static package directory that shadows `__editable__.automation_core-*.pth`, requiring re-syncing on future source edits or switching back to `pip install -e`.

### 2. Reinstall Editable (--no-deps) with Windows Path Syntax
> **Critical Pitfall:** Windows `pip.exe` invoked from Git Bash / MSYS rejects POSIX paths like `/d/Taadaa/...` (`ERROR: /d/Taadaa/... is not a valid editable requirement`). Always pass Windows path format:
```bash
/d/Taadaa/python-envs/automation/Scripts/pip install -e 'D:\Taadaa\automation-core' --no-deps
```

### 3. Verify Live Link & Invariant
```bash
# Verify path points to live repo src
/d/Taadaa/python-envs/automation/Scripts/python.exe -c "import automation_core.alerts as a; print(a.__file__); assert 'Chi tiết 5 bước' not in open(a.__file__, encoding='utf-8').read()"

# Run focused unit tests
/d/Taadaa/python-envs/automation/Scripts/python.exe -m pytest 'D:\Taadaa\automation-core\tests\test_alerts.py' -k test_send_farm_machine_alert

### 4. Immediate Testing Bypass via PYTHONPATH
When rapidly iterating on `automation-core` tests without risking stale `site-packages` or external venv pollution in `sys.path`, always set `PYTHONPATH` to point to the repository's `src` directory:
```bash
PYTHONPATH="D:/Taadaa/automation-core/src" /d/Taadaa/python-envs/automation/Scripts/pytest.exe D:/Taadaa/automation-core/tests/...
```
This forces Python to resolve `automation_core` directly from the working tree before consulting `site-packages`.
