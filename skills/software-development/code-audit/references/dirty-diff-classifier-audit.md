# Dirty-Diff Classifier Audit Reference

## Scope

Use for read-only audits of a dirty TikTok registration worktree before a code fix or live run. Do not open workbooks, credential stores, mailbox contents, device artifacts, or ADB/live state.

## Evidence matrix

| Check | Evidence | Blocking condition |
|---|---|---|
| Dirty boundary | `git status --short`, `git diff --stat` | Scope cannot distinguish target diff from unrelated edits |
| Producer contract | classifier symbol, return values, signature | Missing symbol or return contract differs from tests/callers |
| Propagation | every direct caller and handler call | Mode/context is dropped or inferred again downstream |
| Fresh evidence | foreground/package guard and post-submit recapture | Non-TikTok or stale UI can classify |
| Routing | login vs signup surface plus numeric vs magic-link | Shared marker decides account ownership or mode |
| Fail closed | ambiguous mode and handler side-effect guard | `unknown` reaches reader, resend, login, or registration |
| Registered handoff | canonical login continuation | Registration path attempts to overwrite/continue an existing account |
| Tests | focused suite plus source-level probe | Missing symbols, collection errors, or green-only contract |

## Disposable probe recipe

Run from the repository with the normal native Windows Python, but keep all generated bytecode outside the repository:

```sh
tmp=$(mktemp -d)
PYTHONPYCACHEPREFIX="$tmp" env -u PYTHONPATH python -m py_compile social_reg_v1.py tiktok_login_v1.py
# remove the disposable temp directory using the host-approved cleanup method
```

A source-level probe should:

1. Import the target module and print only symbol presence/signatures, never account values.
2. Exercise redacted XML fixtures for: login numeric, signup numeric, signup magic-link, ambiguous marker, and non-TikTok foreground.
3. Assert that `unknown` is returned for ambiguous/non-TikTok input.
4. Instrument or stub mailbox readers, resend, and registration side effects; assert their call lists remain empty for `unknown`.
5. Assert that the classifier's explicit mode reaches the handler rather than being recomputed from the stale current screen.

## Cross-cutting caller inventory

A focused suite can pass while a production/live caller still uses the old context-free API. Before approval, enumerate every call site with an AST or equivalent source-level probe and record whether the required context/mode keyword is present. For example:

```python
import ast
from pathlib import Path

for path in Path('.').glob('*.py'):
    tree = ast.parse(path.read_text(encoding='utf-8'))
    for node in ast.walk(tree):
        if isinstance(node, ast.Call) and isinstance(node.func, ast.Name):
            if node.func.id == 'detect_after_continue':
                has_surface = any(k.arg == 'entry_surface' for k in node.keywords)
                print(path, node.lineno, has_surface)
```

Apply the same inventory to downstream mode consumers such as `handle_tiktok_email_otp(..., signup_mode=...)`. A caller that omits context is a runtime routing defect, not merely a missing test, when it can classify a real login/signup surface incorrectly. Inspect both normal and live entrypoint modules; do not infer complete propagation from the files named in the diff.

## Classification rules

- **P0:** missing producer/consumer wiring that can route signup into the wrong numeric/magic-link branch, invoke resend, or defeat fail-closed behavior.
- **P0:** a production caller still uses a context-free heuristic and can misclassify a real account/signup screen.
- **P1:** incomplete regression matrix, stale documentation, or a non-production caller that does not yet violate the runtime invariant.
- Do not downgrade a failing test to a test-only issue when the failure demonstrates that the implementation does not provide the promised API.

## Reporting shape

The first line must be exactly one verdict token: `APPROVED`, `MINOR_FIXES`, or `REJECT`. Follow with concise P0/P1 bullets containing exact `file:line` locators and the smallest repair sequence: producer -> propagation -> consumer -> regression matrix. End with the read-only verification results and an explicit statement that ADB/live/workbook/credential actions were not performed.
