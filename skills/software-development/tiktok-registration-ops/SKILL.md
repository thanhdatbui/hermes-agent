## Outlook app Archive-vs-Inbox gate for every Hotmail/Outlook OTP read

Use this gate whenever a TikTok registration or post-auth verification needs a Hotmail/Outlook/Live mailbox. The Outlook app may open on **Archive/Lưu trữ** while the Archive explanation contains the words “Inbox/Hộp thư đến”; broad text matching is not an Inbox proof.

1. **Preflight the exact target before retrying**: verify machine→serial mapping, active worker/lock ownership, target email mapping, and a fresh screenshot/UI dump from the same device. Do not retry from stale JSON, a stale screenshot, or an exit code alone. If an active owner/lock remains, stop and report it; do not reclaim or delete it.
2. **Classify the current Outlook surface structurally**: require the Outlook package plus the messages-list resource and an exact folder heading. `Lưu trữ`/`Archive` means Archive; `Hộp thư đến`/`Inbox` means Inbox only when Archive is absent. Text in the empty-state explanation or CTA must never promote Archive to Inbox.
3. **Archive transition is semantic and bounded**: tap only the visible `ĐI ĐẾN HỘP THƯ ĐẾN`/`GO TO INBOX` node, then recapture and wait for a fresh Inbox classification. Missing CTA, missing recapture, or a second Archive screen is `LoginBlocked`; do not use coordinates, app-data reset, logout, mailbox switching, or blind resend as a substitute.
4. **Prove the mailbox identity separately**: verify the exact drawer summary resource for the requested mailbox. An email address in a message body/snippet is not identity proof. If the drawer cannot prove the target, fail closed before scanning or retrying OTP.
5. **Only then read the TikTok message**: extract from a TikTok-labelled subtree, accept a code only after the Inbox + identity proofs, and write a redacted artifact containing status/package/activity—not the mailbox or OTP. A missing/old code is a read failure, not permission to loop resend blindly.
6. **Keep provider ownership canonical**: `Hotmail/flows/hotmail_login.py` owns the Outlook-app reader; `Tiktok_Reg/hotmail_provider.py` is only an adapter; every Gmail/non-Gmail post-auth call site must route through the provider dispatcher. Grep all call sites when changing routing—fixing only the primary OTP path leaves `[8b]`/`[9]` blind-resend regressions.
7. **Verification gate before live retry**: run the focused reader/login tests, provider/post-auth tests, `py_compile`, and `git diff --check`; review the actual diff and artifact schema. Do not run machine retry until the fresh live preflight proves the target is safe and the canonical reader is the code under test.
