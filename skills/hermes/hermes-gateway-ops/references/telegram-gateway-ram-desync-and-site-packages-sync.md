# Bẫy Lệch Pha RAM & Mã Nguồn: Python Gateway Long-Running vs Runtime Sync

## 1. Hiện Tượng & Triệu Chứng
- Code vá lỗi mạng/tải ảnh đã được commit vào git và ghi vào file `.py` trên ổ cứng (ví dụ `_download_telegram_file_with_retry` trong adapter).
- Nhưng người dùng thử nghiệm thực tế vẫn bị văng lỗi cũ (như cảnh báo không tải được ảnh).
- **Nguyên nhân cốt lõi**: Tiến trình Daemon Gateway (`pythonw.exe -m hermes_cli.main gateway run`) là tiến trình chạy dài (long-running). Python chỉ load module vào RAM lúc import khi tiến trình khởi động. Nếu Gateway không được restart, toàn bộ sửa đổi trên đĩa hoàn toàn vô hiệu hóa trong RAM.

## 2. Bẫy Tử Huyệt Khi Restart: Bán Đồng Bộ `site-packages` (Partial Sync / Incomplete Dependency)
- **CẤM TUYỆT ĐỐI copy đơn lẻ file `.py` từ repo vào `site-packages`:**
  * Copy lẻ từng file (ví dụ chỉ copy `gateway/run.py` và `gateway/platforms/base.py`) rất dễ gây crash toàn bộ Gateway do lệch phụ thuộc liên module (cross-module import drift).
  * **Sự cố thực tế (13/10/2026):** Agent copy `gateway/run.py` bản mới từ repo vào venv. Bản này import `reasoning_efforts_for_model` từ `hermes_constants`. Trong khi đó `hermes_constants.py` ở root của venv vẫn là bản cũ chưa có hàm này. Kết quả: Mọi tin nhắn Telegram gửi tới đều crash ngay lập tức với `ImportError`, Gateway trả về *"Sorry, I encountered an unexpected error"* hàng loạt.
- Khi một agent thực hiện [L2-surgery] hoặc copy chắp vá vài module mới vào `site-packages` mà không đồng bộ các module phụ thuộc mới (ví dụ các module hủy lệnh như `AuxiliaryExplicitCancellation`, `hermes_constants`, hay `hermes_state_common`), tiến trình Gateway đang chạy trong RAM vẫn sống nhờ bytecode cũ.
- Khi người dùng hoặc script thực hiện restart Gateway, tiến trình mới import `site-packages` bị lệch pha và dính `ImportError`, rơi vào vòng lặp crash liên tục.
- **Quy tắc kiểm tra & đồng bộ chuẩn:**
  * Tuyệt đối không copy file lẻ. Khi cần đồng bộ mã nguồn vào venv, BẮT BUỘC dùng `pip install -e .` hoặc đồng bộ trọn vẹn toàn bộ cây runtime từ git HEAD (`agent`, `gateway`, `hermes_cli`, `tools`, `plugins`, `providers`, `cron`, và các module top-level như `hermes_constants.py`).
  * **Pre-flight import test bắt buộc TRƯỚC KHI restart:**
    Trước khi gọi `hermes gateway restart` hoặc script restart, BẮT BUỘC chạy kiểm chứng import sạch trong subshell:
    ```bash
    python -c "import gateway.run, hermes_constants; print('Import OK')"
    ```
    Nếu lệnh này văng bất kỳ lỗi `ImportError` hay `AttributeError` nào, CẤM restart Gateway và phải rollback ngay.
  * Luôn tạo bản sao lưu thư mục `site-packages` hoặc file gốc trước khi sync (ví dụ `hermes_constants.py.bak-<timestamp>`).

## 3. Khắc Phục Kẹt File Lock Mồ Côi Sau Crash
- Khi Gateway hoặc các agent nền bị kill/crash đột ngột giữa chừng, các file lock bảo vệ có thể bị giữ bởi các tiến trình con mồ côi hoặc handle chưa giải phóng trên Windows.
- Điều này kích hoạt cơ chế bảo vệ fail-closed của guard: không thể giành lock sau 3s và mọi tool call bị chặn đứng.
- **Lệnh dọn dẹp an toàn qua PowerShell**:
  Quét và dọn các tiến trình Python phụ/mồ côi không phải gateway hoặc dashboard, sau đó dọn file lock mồ côi trong AppData để khôi phục quyền điều phối.
